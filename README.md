# R&D 프로젝트 일정관리

연구개발 프로젝트별 일정·이슈를 전 직원이 브라우저로 함께 관리하는 사내 웹 프로그램입니다.
지금은 회사 서버 PC 한 대에서 돌리고, 나중에 설정만 바꿔 클라우드(웹 버전)로 옮길 수 있게 만들었습니다.

## 카테고리 (11/24 개정 계획)

프로젝트마다 **연구 · 시공 · 설계** 중 하나를 고르면, 그 업무에 맞는 화면이 먼저 열립니다. 데이터는 같으므로 다른 보기도 탭으로 볼 수 있습니다.

| 카테고리 | 먼저 열리는 화면 | 쓰임 |
|---|---|---|
| 🔬 연구 | 일정(주·월) | 회의(시각·장소·참석자·링크)·시험·마일스톤 D-day, 협약 기간·예시 일정, 칸반 검토(승인/반려). Teams 회의·Outlook 동기화는 3단계 |
| 🏗️ 시공 | 간트 | 상세 스케줄(선행관계·기준 일정). 기존 프로젝트는 모두 시공으로 옮겨짐 |
| 📐 설계 | 칸반 | 할 일을 카드로 만들고 끌어서 열(할 일→진행 중→검토→완료) 이동 |

- **칸반**: 카드를 끌어 다른 열에 놓으면 상태가 바뀌고(완료 열이면 완료일 자동 기록), 같은 열 안에서 끌면 순서가 바뀝니다. 마우스·터치(길게 눌러 끌기)·키보드(스페이스) 지원. 각 열 아래 "+ 할 일 추가"에 제목만 넣고 Enter. 담당·마감·태그·"내 카드만" 필터. 열 이름·색·순서·상태는 프로젝트 설정에서 변경
- **할 일 간편 입력**: 편집창은 제목·담당자·마감일·상태·우선순위·태그·메모·체크리스트만 먼저 보이고, 시작일·단계·유형·선행관계·기준 일정은 "자세히"에서 입력. 마감일을 비우면 날짜 없는 할 일(간트·달력에는 안 보임)
- **할 일 목록**: 정렬·일괄 완료·엑셀 내보내기, 체크리스트 진행률
- **홈·내 할 일**: 세 카테고리의 내 할 일을 한 목록으로(지연·오늘·이번 주·나중·날짜 없음), 카테고리별 현황 카드, 왼쪽 메뉴의 카테고리별 프로젝트 모아 보기

## 주요 기능 (기존)

- **프로젝트 관리**: 프로젝트 추가·수정·보관, 단계(계약·공정·연구 단계) 구성, 참여자와 역할(PM/참여자/조회자)
- **작업(WBS)**: 유형(작업·마일스톤·제출·지급·검토·홀드포인트·회의), 담당, 기간, 상태, 진행률, 핵심★, 계약 조항, 비고
- **선행관계 자동 일정**: 끝나면 시작(FS)·동시 시작(SS)·동시 종료(FF) + 지연일. 선행작업 날짜가 바뀌면 뒤따르는 작업이 자동으로 옮겨짐.
  프로젝트마다 **근무일 기준**(주말·공휴일 제외) 또는 **달력일 기준** 선택. 최초 가능일(이 날짜보다 앞당기지 않음) 지원
- **기준 일정(Baseline)과 편차**: 처음 합의한 일정 대비 늦어진 일수를 간트·작업 정보에 표시
- **화면**: 홈(내 작업·내 이슈·전체 프로젝트 현황), 프로젝트 대시보드, 간트(일/주/월), 달력, 작업 목록, 이슈, 설정
- **이슈 관리**: 중요도·책임기관·목표일·현황, 관련 작업 연결, 댓글
- **엑셀**: 기존 CML 계약 일정 통합본(Detail 시트)·일정표·이슈로그 불러오기, 작업·이슈 엑셀 내보내기(수정 후 다시 불러오기 가능)
- **관리**: 부서(상위·하위), 직원 계정(사번·부서·직급·권한, 엑셀 일괄 등록), 공휴일, DB 백업 현황
- **회의록**: 브라우저에서 회의 녹음(또는 녹음 파일 업로드) → 음성인식(리턴제로, 화자 구분) → AI 정리(Claude: 요약·결정 사항·할 일·이슈) → 할 일·이슈를 작업·이슈로 바로 등록. 설정은 설치 가이드 9단계
- **변경 이력**: 누가·언제·무엇을 바꿨는지 기록, 작업·이슈별 이력 보기
- **동시 수정 보호**: 같은 항목을 다른 사람이 먼저 고쳤으면 덮어쓰지 않고 알려 줌

M365(Teams·Outlook) 연동은 개발 막바지에 추가합니다. 그 전까지는 프로그램 자체 계정으로 로그인합니다.

## 설치·실행 (Windows)

자세한 순서는 **[docs/설치가이드_Windows.md](docs/설치가이드_Windows.md)** 를 보세요. 요약:

1. Node.js LTS, Git, PostgreSQL 설치
2. `git clone https://github.com/youngchanjung/project.git schedule`
3. `setup-db.bat` → DB·계정 생성, `.env` 작성
4. `start-server.bat` → <http://localhost:3000> 접속, 첫 관리자 계정 만들기
5. **관리** 화면에서 부서·직원(엑셀 일괄 등록 가능)·권한·공휴일 입력
6. `register-backup-task.bat` (관리자 권한) → 매주 금요일 19:00 자동 DB 백업

## 기존 엑셀 가져오기

1. 홈에서 **+ 새 프로젝트** → 이름 입력 → 만들기
2. **설정 → 엑셀 불러오기**에서 파일 선택(여러 개 가능) → **미리 보기**로 인식 결과 확인 → **불러오기 실행**

지원 형식
- 계약 일정 통합본: `00_General Detail` ~ `05_Supervision Detail` 시트 + `Holidays`(베트남 공휴일).
  선행작업·지연일·동시 시작/종료가 선행관계로 들어오고, 엑셀이 달력일 기준이므로 프로젝트도 달력일 기준으로 맞춰집니다.
  엑셀에서 시작일을 직접 입력한 작업은 입력값을 그대로 쓰고, 원래 선행관계는 비고에 남깁니다.
- 일정표·이슈로그: `일정표_Schedule`, `이슈로그_IssueLog` 시트 (작업 ID는 `S-번호`)
- 이 프로그램에서 내보낸 엑셀: `작업`, `이슈` 시트

ID(이슈 No)가 같은 항목은 갱신하고, 없는 항목은 추가합니다. 기존 데이터는 지우지 않습니다.

## 웹 버전(클라우드)으로 옮기기

- 서버 PC 와 같은 PostgreSQL 을 쓰므로 `.env` 의 `DATABASE_URL` 만 클라우드 DB 주소로 바꾸면 됩니다. 데이터는 백업(.dump)을 복원해 옮깁니다.
- HTTPS 로 서비스할 때는 `SECURE_COOKIE=true`.

설정 항목은 `.env.example` 참고.

## 개발

```
npm install
npm run dev        # API(3000) + 화면 개발 서버(5173, /api 는 3000으로 전달)
npm test           # 일정 계산·관리 기능 테스트 (임시 SQLite 사용)
npm run backup     # 지금 DB 백업
npm run build      # 화면 빌드 → web/dist (서버가 함께 제공)
```

구조
```
server/src
  index.js          서버 시작, 라우팅
  config.js, db.js  설정, DB 연결 (SQLite / PostgreSQL)
  migrations.js     DB 구조 (새 변경은 배열 끝에 추가)
  schedule.js       근무일·선행관계 일정 계산
  excel.js          엑셀 불러오기/내보내기
  auth.js           로그인·권한 (M365 연동 시 확장)
  backup.js         DB 백업 (pg_dump / SQLite 사본)
  stt.js            음성인식 (리턴제로)
  minutesAI.js      회의록 AI 정리 (Claude)
  routes/           API (org.js: 직원·부서, backup.js: 백업 현황, meetings.js: 회의록)
web/src
  pages/            홈, 프로젝트, 관리, 로그인
  views/            대시보드, 간트, 달력, 작업 목록, 이슈, 회의록, 설정
  components/       작업·이슈 편집 창, 변경 이력
```
