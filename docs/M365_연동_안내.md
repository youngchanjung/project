# Microsoft 365 · Teams 연동 안내 (IT 담당자용)

R&D 일정관리 프로그램을 회사 Microsoft 365 에 연결하는 방법입니다.
**`.env` 에 값을 넣고 서버를 다시 시작하면 켜집니다.** 값이 없으면 연동만 꺼지고 아이디·비밀번호 로그인과 화면 알림(🔔)은 그대로 동작합니다.

| 기능 | 필요한 것 | 켜지는 내용 |
|---|---|---|
| 회사 계정 로그인 (SSO) | 앱 등록 + 위임 권한 `openid` `profile` `email` | 로그인 화면에 "회사 계정(Microsoft)으로 로그인" 버튼. 처음 로그인하면 메일 주소로 기존 직원과 연결(없으면 자동 등록) |
| 메일 알림 | 앱 권한 `Mail.Send` + 보내는 사서함 | 🔔 알림을 회사 메일로도 보냄 (담당 지정, 일정 변경, 마감 임박, 검토 요청, 회의 초대 등). 직원별로 🔔 에서 끌 수 있음 |
| Outlook 일정 | 앱 권한 `Calendars.ReadWrite` | 회의(유형 '회의')를 담당자 Outlook 에 등록하고 참석자에게 초대. 'Teams 회의 만들기'를 켜면 Teams 링크 자동 생성. 담당 작업은 담당자 달력에 종일 일정(바쁨 표시 안 함·알림 없음) |
| Teams 채널 알림 | 앱 등록 필요 없음. 채널의 워크플로 웹후크 주소 | 프로젝트별 채널에 검토 요청·승인·반려, 회의 초대, 새 이슈 카드와 매일 아침 일정 요약 |

> Outlook 일정은 **프로그램 → Outlook 한 방향**입니다. Outlook 에서 고친 내용은 프로그램으로 돌아오지 않고, 다음에 프로그램에서 그 작업을 고치면 프로그램 내용으로 덮어씁니다.

## 1. Entra ID 앱 등록 (전역 관리자 또는 애플리케이션 관리자)

1. <https://entra.microsoft.com> → **ID → 애플리케이션 → 앱 등록 → 새 등록**
   - 이름: `R&D 일정관리`
   - 지원되는 계정 유형: **이 조직 디렉터리의 계정만 (단일 테넌트)**
   - 리디렉션 URI: 플랫폼 **웹(Web)**, 주소 `https://<서버 주소>/api/auth/m365/callback`
     - 예: `https://schedule.회사.co.kr/api/auth/m365/callback`, 사내 PC 이름이면 `https://SERVERPC:3000/api/auth/m365/callback`
     - 개발 PC 에서 시험할 때는 `http://localhost:3000/api/auth/m365/callback` 도 추가 (localhost 만 http 허용)
2. 등록 후 **개요** 화면에서 두 값을 적어 둡니다.
   - 디렉터리(테넌트) ID → `M365_TENANT_ID`
   - 애플리케이션(클라이언트) ID → `M365_CLIENT_ID`
3. **인증서 및 비밀 → 새 클라이언트 비밀** → 설명 `일정관리 서버`, 만료 24개월 → 생성된 **값**을 바로 복사 → `M365_CLIENT_SECRET`
   - 값은 이 화면을 떠나면 다시 볼 수 없습니다. 만료일을 달력에 적어 두고 만료 전에 새 비밀을 만들어 `.env` 를 바꾸세요.
   - 이 값은 `.env` 에만 넣고, 메일·메신저·문서에 붙여 넣지 마세요.
4. **API 권한 → 권한 추가 → Microsoft Graph**
   - **위임된 권한**: `openid`, `profile`, `email` (로그인용. `User.Read` 는 기본으로 있어도 됨)
   - **애플리케이션 권한**: `Mail.Send` (메일 알림을 쓸 때), `Calendars.ReadWrite` (Outlook 일정을 쓸 때)
   - **[회사 이름]에 대한 관리자 동의 허용** 클릭 → 상태가 모두 녹색 ✓ 인지 확인
5. (선택) **엔터프라이즈 애플리케이션 → R&D 일정관리 → 속성 → 할당 필요 = 예** 로 두고 **사용자 및 그룹**에 사용할 직원·그룹만 추가하면, 그 사람들만 회사 계정으로 로그인할 수 있습니다.

### 메일·일정 권한 범위 줄이기 (권장)

애플리케이션 권한 `Mail.Send`, `Calendars.ReadWrite` 는 기본적으로 **회사 전체 사서함**에 적용됩니다.
보안 규정상 범위를 줄여야 하면 Exchange Online 의 **애플리케이션 RBAC** 으로 대상 사서함을 제한하세요. (IT 담당자가 Exchange Online PowerShell 에서 실행)

```powershell
Connect-ExchangeOnline
# 1) 메일 사용 보안 그룹 만들기 (예: schedule-users@회사) → 보내는 사서함과 일정관리 사용 직원을 넣음
# 2) 앱을 Exchange 에 등록 (ObjectId 는 엔터프라이즈 애플리케이션의 '개체 ID')
New-ServicePrincipal -AppId <클라이언트 ID> -ObjectId <엔터프라이즈 앱 개체 ID> -DisplayName "R&D 일정관리"
# 3) 그 그룹만 대상으로 하는 범위
New-ManagementScope -Name "일정관리 대상" -RecipientRestrictionFilter "MemberOfGroup -eq '<그룹의 DistinguishedName>'"
# 4) 범위 안에서만 메일 보내기·일정 쓰기
New-ManagementRoleAssignment -App <클라이언트 ID> -Role "Application Mail.Send" -CustomResourceScope "일정관리 대상"
New-ManagementRoleAssignment -App <클라이언트 ID> -Role "Application Calendars.ReadWrite" -CustomResourceScope "일정관리 대상"
# 확인
Test-ServicePrincipalAuthorization -Identity <클라이언트 ID> -Resource <직원 메일>
```

이 방식을 쓸 때는 4단계의 **애플리케이션 권한 `Mail.Send`·`Calendars.ReadWrite` 에 관리자 동의를 하지 않습니다** (동의하면 다시 회사 전체로 넓어짐). 위임 권한(`openid` `profile` `email`)만 동의하세요.
명령과 화면 이름은 Microsoft 가 바꾸는 경우가 있으니 최신 문서("Exchange Online 애플리케이션용 RBAC")를 함께 확인하세요.

## 2. 보내는 사서함 준비 (메일 알림)

- 알림을 보낼 사서함을 정합니다. 예: 공유 사서함 `schedule@회사.co.kr` (공유 사서함은 라이선스가 필요 없음)
- `.env` 의 `M365_MAIL_FROM` 에 그 주소를 넣습니다.
- 직원 계정에 **메일 주소**가 있어야 메일을 받습니다. (관리 → 직원 계정, 또는 회사 계정으로 한 번 로그인하면 자동으로 채워짐)

## 3. `.env` 설정

서버 PC 의 `.env` 에 아래 값을 넣고 서버를 다시 시작합니다. (예시는 `.env.example` 의 "Microsoft 365" 부분)

```ini
# 필수 (앱 등록 값)
M365_TENANT_ID=00000000-0000-0000-0000-000000000000
M365_CLIENT_ID=00000000-0000-0000-0000-000000000000
M365_CLIENT_SECRET=(클라이언트 비밀 값)
# 직원이 접속하는 주소 (메일·Teams 카드의 바로가기 링크, 로그인 리디렉션에 사용)
PUBLIC_URL=https://schedule.회사.co.kr
# 리디렉션 URI 를 PUBLIC_URL 과 다르게 등록했을 때만
# M365_REDIRECT_URI=https://schedule.회사.co.kr/api/auth/m365/callback

# 메일 알림 (비우면 메일만 꺼짐)
M365_MAIL_FROM=schedule@회사.co.kr
# 메일로 보낼 알림 종류만 고르려면 (비우면 전부)
# M365_MAIL_KINDS=task_assigned,review_requested,meeting_invited,task_due,task_late,milestone_due

# 로그인 방식: all = 회사 계정 + 아이디 모두, admin = 아이디 로그인은 관리자만 (비상용)
M365_LOCAL_LOGIN=all
# 처음 로그인한 회사 계정을 직원으로 자동 등록 (false 면 관리자가 미리 등록한 메일 주소만)
M365_AUTO_CREATE=true

# Outlook 일정 (false 면 끔)
M365_OUTLOOK=true
# 회의뿐 아니라 담당 작업도 담당자 달력에 종일 일정으로 (false 면 회의만)
M365_OUTLOOK_TASKS=true
# 시간대 (비우면 프로젝트 휴일 달력이 VN 이면 SE Asia Standard Time, 아니면 Korea Standard Time)
# M365_TIMEZONE=Korea Standard Time

# 하루 한 번 마감·마일스톤 알림과 Teams 아침 요약을 보내는 시각 (기본 8시)
DAILY_NOTIFY_HOUR=8
```

서버를 시작하면 창에 `M365 연동: 로그인 켜짐 · 메일 켜짐 · Outlook 켜짐` 처럼 표시됩니다.

## 4. 확인

1. 관리자로 로그인 → **관리 → Microsoft 365 연동** 카드에서 켜진 기능 확인
2. **시험 메일** → 내 메일함에 "[R&D 일정관리] 시험 메일" 이 오는지 확인
3. 로그아웃 → **회사 계정(Microsoft)으로 로그인** → 처음 한 번 동의 화면이 나오면 동의
4. 아무 프로젝트에서 유형 '회의', 일시·참석자를 넣고 **Teams 회의 만들기** 체크 → 저장 → 몇 초 뒤 담당자 Outlook 달력과 참석자 메일함 확인, 작업의 '회의 링크'에 Teams 주소가 채워짐
5. 실패하면 같은 카드의 **최근 기록 / Outlook 일정 실패** 에 Microsoft 의 오류 문구가 나옵니다. 고친 뒤 **Outlook 다시 맞추기**

자주 나오는 오류
- `AADSTS50011 ... redirect URI` → 1단계 리디렉션 URI 와 `PUBLIC_URL`(또는 `M365_REDIRECT_URI`) 이 글자 하나까지 같은지 확인
- `AADSTS7000215 invalid client secret` → 비밀 값이 아닌 '비밀 ID' 를 넣었거나 만료됨
- `Access is denied` / `ErrorAccessDenied` (메일·일정) → 관리자 동의를 안 했거나, RBAC 범위에 그 사서함이 없음
- `MailboxNotEnabledForRESTAPI` → 그 직원에게 Exchange Online 사서함(라이선스)이 없음

## 5. Teams 채널 알림 (프로젝트별)

앱 등록 없이 채널마다 설정합니다. (Office 365 커넥터의 '수신 웹후크'는 Microsoft 가 종료 중이라 **워크플로**를 씁니다)

1. Teams 에서 프로젝트 채널 → 채널 이름 옆 **⋯ → 워크플로**
2. 템플릿 **"웹후크 요청이 수신되면 채널에 게시"** (Post to a channel when a webhook request is received) 선택 → 팀·채널 확인 → **워크플로 추가**
3. 만들어진 **주소(URL)를 복사**
4. 일정관리 프로그램 → 그 프로젝트 → **설정 → Teams 채널 알림** 에 붙여 넣기 → 저장 → **시험 보내기**

- 주소를 아는 사람은 누구나 그 채널에 글을 올릴 수 있으니 비밀번호처럼 다루세요. 프로그램에서는 그 프로젝트의 PM 만 보고 바꿀 수 있습니다.
- 채널로 가는 것: 칸반 검토 요청·승인·반려, 회의 초대, 새 이슈, 매일 아침(DAILY_NOTIFY_HOUR) 요약(오늘 회의, 마일스톤·단계 제출일 D-7·D-1·당일, 기한 지난 작업)

## 6. Teams 채널 탭 (선택)

채널 위쪽 **+ (탭 추가) → 웹사이트** → 이름 `일정관리`, 주소 `https://<서버 주소>/projects/<프로젝트 번호>/dashboard`
- 프로젝트 번호는 프로그램에서 프로젝트를 열었을 때 주소창의 `/projects/숫자` 입니다.
- Teams 안에서는 Microsoft 로그인 화면이 막히는 경우가 있습니다. 로그인 창이 안 뜨면 탭 오른쪽 위 **브라우저에서 열기**를 쓰세요.

## 7. 개인정보·보안 메모

- 프로그램이 Microsoft 로 보내는 것: 알림 문구(작업·이슈 이름, 날짜), 회의·작업 일정(이름·일시·장소·참석자·메모), Teams 카드 문구
- 클라이언트 비밀은 `.env` 에만 있고 화면에 나오지 않습니다. Teams 웹후크 주소는 그 프로젝트 PM 화면에만 보이고 변경 이력에는 `••••` 로 남습니다.
- DB 백업 파일에는 웹후크 주소가 들어 있으니 백업 폴더는 관리자만 열 수 있게 두세요.
- 연동을 끄려면 `.env` 의 `M365_CLIENT_SECRET` 을 지우고(또는 `M365_OUTLOOK=false` 등) 서버를 다시 시작하세요. 이미 만들어진 Outlook 일정은 남아 있으니, 지우려면 끄기 전에 프로젝트를 보관하거나 작업을 지우세요.
